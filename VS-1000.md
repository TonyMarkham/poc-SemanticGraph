# VS-1000: Durable Decisions For SemanticGraph MCP And Agent Assets

## Purpose

Record the concrete Phase 0 decisions that downstream VS-100 implementation
phases must follow.

`VS-100.md` remains the initiative outline. `VS-110.md` records the Phase 0
preflight plan and supporting evidence. This document is the durable decision
record for implementation.

## Status

Accepted for downstream planning and implementation.

## Decision 1: Codex Project-Local Paths

Generated Codex assets for downstream projects must be project-local.

Skill outputs:

```text
.agents/skills/semantic-graph/SKILL.md
.agents/skills/semantic-graph/references/*.md
```

Custom-agent outputs:

```text
.codex/agents/semantic-graph-explorer.toml
.codex/agents/semantic-graph-route-verifier.toml
.codex/agents/semantic-graph-rust-refresh.toml
.codex/agents/semantic-graph-csharp-refresh.toml
.codex/agents/semantic-graph-plan-auditor.toml
```

Project Codex config:

```text
.codex/config.toml
```

Managed install metadata:

```text
.codex/semantic-graph/install-manifest.json
.codex/semantic-graph/README.md
```

The generated MCP config table name is:

```toml
[mcp_servers.semantic_graph]
```

## Decision 2: No Installable Smoke Agent

Do not generate or install a smoke-test custom agent for downstream projects.

Smoke verification may be useful in this development repository, but it belongs
in deterministic tests, `semantic-graph doctor codex`, or a future
developer-only smoke command.

Downstream custom agents are limited to graph exploration, route verification,
Rust refresh, C# refresh, and plan auditing.

## Decision 3: Preserve SemanticGraph Config Compatibility

Do not rename or migrate the existing SemanticGraph config path as part of the
MCP, skill, or installer work.

Current database discovery through `.refactor-radar/config.toml` must remain
compatible. Later Codex installer work may write `.codex/config.toml`, but that
Codex config is for Codex behavior and MCP registration, not a replacement for
the existing SemanticGraph database config.

## Decision 4: Visualizer Is A Local Testbed

The current Blazor/JSON-RPC visualizer is not a durable product target for this
repo.

Treat these surfaces as current local testbed evidence:

```text
apps/SemanticGraph.Visualizer
crates/semantic-graph-visualizer-server
```

They may provide:

- a local C# project for C# semantic extraction testing;
- prior art for read-only graph projection queries;
- optional smoke coverage while they remain present.

They must not define the durable MCP, query, skill, or installer boundaries.

## Decision 5: `semantic-graph-query` Is The Durable Query Boundary

Phase 1 must create a durable shared query crate:

```text
crates/semantic-graph-query
```

The current visualizer-server query code is useful prior art, but it should not
become the public query boundary. MCP models must not be shaped by visualizer
DTO names.

The shared query crate owns transport-neutral read models and SQLite-backed
query behavior for:

- stats;
- node search;
- node details;
- edge details;
- projection;
- neighbors;
- shortest path;
- file summary;
- route status.

MCP-specific DTOs belong in the MCP server crate. Optional local testbed DTOs
belong outside the shared query crate.

## Decision 6: MCP MVP Is Read-Only Stdio First

The first MCP implementation must be read-only and stdio-first.

Default command shape:

```sh
semantic-graph-mcp-server \
  --database-path .local/rust-workspace-extract.db \
  --transport stdio
```

HTTP transport and mutating extraction tools are later work. If HTTP is added,
it must keep the VS-100 loopback and API-key requirements. If extraction tools
are added, they must remain disabled unless explicitly gated.

## Decision 7: MCP SDK Adoption Requires A Spike

Do not add a Rust MCP SDK by default.

Before adopting one, Phase 2 must record:

- crate name and version;
- maintenance status;
- protocol features needed for tools and resources;
- stdio support;
- structured output support;
- error handling fit with `thiserror` and `error-location`;
- dependency impact;
- testability with fixture SQLite databases.

If the SDK is not clearly better for this repo, implement the narrow local
stdio MCP subset needed for the read-only MVP.

## Downstream Phase Guidance

Phase 1 must implement `semantic-graph-query` before MCP transport work.

Phase 2 must consume `semantic-graph-query` from a separate
`semantic-graph-mcp-server` crate.

Agent asset generation and installation must use the project-local Codex paths
recorded here.

Validation and smoke behavior must be deterministic first. Use custom agents
only where judgment, graph evidence review, or scoped refresh workflows are
actually useful.
